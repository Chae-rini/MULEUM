# 디자인 시스템 — Soft Blue Library

## 콘셉트 — 낮에는 맑은 하늘, 밤에는 별빛 아래의 도서관

처음 콘셉트는 "구름 위에 떠 있는 도서관"이었다. 2026-10-25 앱 아이콘이 물음표로 바뀌면서 구름 장식은 모두 뺐다. 지금은 하늘과 별만으로 낮과 밤을 표현한다.

낮에는 태양빛, 밤에는 별빛이 비추고, 두 빛이 함께 있다. Soft Blue Library를 바꾸지 않고 심화한다.

- **라이트 = 낮, 맑은 하늘**: 위는 하늘색이고 아래로 갈수록 밝아져 페이지 바탕으로 이어진다.
- **다크 = 밤, 별과 은하를 보는 도서관**: 시스템 설정(`prefers-color-scheme: dark`)만 따른다. 수동 전환 버튼은 없다.
- **공존 원칙**: 낮에도 별(✦ 모티프)이 작게 남는다. 밤에도 태양빛이 독서등(따뜻한 종이색 `--reading-light`)으로 남는다.
- **장식이 있는 곳**: 풍경 장식(하늘·✦·밤의 별)은 공개 홈, 로그인·초대·첫 로그인 확인 화면에만 둔다. 회원 학습 공간(질문·일기 등)은 장식을 최소화해 읽기에 집중하게 한다.
- **장식 규칙**: 모두 CSS와 인라인 SVG로만 만든다(`components/sky.tsx`). 이미지나 외부 요청은 쓰지 않는다. 화면낭독기에는 숨긴다(`aria-hidden`). 장식 위의 모든 글자는 대비 기준(본문 4.5:1, 큰 글자 3:1)을 지킨다. 움직임은 `prefers-reduced-motion`에서 완전히 멈춘다.

### 라이트 모드에서 쓰는 곳 (2026-10-24)

- **홈 히어로**
  - 도서관 사진은 유지하고, 남색 덮개 대신 하늘색 덮개(`--sky-top`)를 씌운다. 글자는 남색이다.
  - 글자가 놓이는 영역은 덮개가 92% 이상(`--hero-scrim`)이다. 사진이 완전히 검은 점이어도 본문 9.7:1, 큰 제목의 강조 파랑 3.55:1이다. `tests/design.test.ts`가 계산한다.
  - 강조 파랑은 큰 제목에만 쓰고, 작은 글자는 남색을 쓴다. 넓은 화면에서는 오른쪽으로 갈수록 덮개가 옅어져(55%) 사진이 드러난다.
  - 아래쪽 24%는 다음 섹션의 바탕색(`--hero-fade`)으로 부드럽게 이어진다. 낮에는 흰색, 밤에는 밤하늘색이다.
- **로그인·초대·첫 로그인 확인 화면의 머리 띠(`.auth-intro`)**: 하늘색에서 옅은 하늘을 거쳐 페이지 바탕으로 이어진다.
- **✦(`Sparkle`)**: 홈 섹션 표시(01~04, BETA), 히어로·로그인 띠의 머리글에만 작게 둔다.
- **더 밝은 낮 (2026-10-24, 2단계 적용)**
  - 회원 화면 제목 띠와 홈 '철학' 섹션이 남색 띠에서 **밝은 하늘 띠**(`--band` #E6F1FA)로 바뀌었다. 글자는 남색, 머리글은 강조 파랑이다.
  - 페이지 바탕은 베이지에서 흰 하늘빛(`--page` #F8FBFF)으로 바뀌었다. 하늘색(`--sky-top`)도 한 톤 밝은 #E3EFFB가 되었다.
  - 버튼은 남색으로 둬서 누를 곳이 뚜렷하다. 일기 등 읽기 표면과 홈의 종이색 섹션은 독서등(따뜻한 종이색)으로 남긴다.
  - 다크 모드는 바뀌지 않았다. 다크 스크린샷 12장이 이전과 픽셀까지 같다.
  - 비교 이미지: `artifacts/brighter-preview/`(단계별 미리보기), `artifacts/brighter-light/`(적용 전후).

### 다크 모드에서 쓰는 곳 (2026-10-24)

- **바탕**: 딥 네이비 `#0B1426`에서 보랏빛 남색 `#1D1A3F`로 내려가는 그라데이션(`--page-glow`)이다. 카드는 반투명 남색(`#15233F`, 84%)이고 경계는 옅은 별빛(`#2B3B5E`)이다.
- **두 빛의 공존**
  - 별빛 포인트(차가운 하늘색 `#8EC5FF`): 링크, 초점, 주요 버튼.
  - 독서등(따뜻한 종이색): 회원 화면 제목 띠의 머리글(`#F0D29A`), 일기 등 읽기 표면(`#2A2419`), 홈의 종이색 섹션.
- **홈 히어로**: 도서관 사진은 밤 덮개(`--sky-top` 다크값, 글자 영역 90%·먼 쪽 80%)로 어둡게 한다. 그 위에 별(`NightSky`)과 옅은 은하 띠를 그린다. 사진 출처 문구는 그대로 사실이다.
  - **별**: 고정 시드로 위치를 정한 70개다. 화면을 다시 열어도 같다. 그중 6분의 1이 7초 주기로 느리게 반짝이고, 움직임 줄이기에서는 멈춘다.
  - **별이 글자 아래에 오는 문제**: 글자 칸 쪽으로 갈수록 별을 흐리게 했다(마스크).
  - **대비**: 사진이 완전히 흰 점이어도 히어로 본문·강조 글자가 4.5:1 이상이다(`tests/design.test.ts`).
  - **아래쪽**: 밤하늘색으로 이어진다.
- **로그인·초대·첫 로그인 확인 띠**: 밤하늘 그라데이션이다. 별 배경은 없다.
- **회원 학습 공간**: 별 배경을 깔지 않는다. 다크 표면과 독서등 색만 쓴다.
- **역할 토큰**: 낮에는 같은 남색이지만 밤에는 역할이 갈라지는 색을 분리했다. 띠 배경 `--band`·`--on-band`·`--band-eyebrow`, 페이지 `--page`·`--page-glow`, 바탕 `--ground`, 완료 표시 `--chip`, 히어로 아래쪽이 이어지는 색 `--hero-fade`, 하늘 아래쪽 `--sky-low`다. 라이트 값은 이전과 같다. 홈·로그인·마이페이지·질문 화면 12장을 분리 전후로 비교했고 픽셀까지 같았다.
- **주소창 색**: 낮에는 흰색, 밤에는 `#0B1426`이다(`app/layout.tsx`의 viewport `themeColor`).
- **앱 아이콘(보고만 함)**: 화면 로고는 원본의 흰 여백과 밝은 배경을 그대로 쓴다. 그래서 다크 헤더·로그인 띠 위에서 **밝은 흰 타일**처럼 도드라진다. 투명 배경이나 다크 전용 로고는 따로 정해야 한다.

## 색 토큰

공통 원본은 `app/theme.css`다. 공개 홈페이지·로그인·마이페이지·역할별 회원 화면은 같은 색상 토큰과 `app/globals.css`를 사용한다. `components/public-home.module.css`의 `--home-*` 이름은 모두 이 토큰을 가리키는 별칭이고, 색 값을 직접 쓰지 않는다(`tests/design.test.ts`가 검사한다). Card, Heading, Field, Feedback의 기능은 유지한다. 새 패키지나 외부 폰트를 추가하지 않았다.

아래 표는 2026-10-24 실제 `theme.css` 값이다. 이전 표(#3567B7 등)는 홈 v2 색으로 바꾸면서 갱신되지 않은 상태였다.

- `sky-top`은 작은 보조 글자(#5B6778)가 위에 놓여도 4.5:1 이상이 되도록 정한다. 처음 값 #D6E8F8은 4.58:1이었고, 밝게 바꾼 #E3EFFB에서는 더 높다.
- 반투명 색은 `color-mix(in srgb, var(토큰) N%, transparent)`로 만든다.

주요 버튼은 흰색 글자와 남색(brand-action)을 사용한다. Hover #2F6FA8, Active #1E2A3A이며 비활성 버튼은 중립 배경과 짙은 보조 글자로 표시한다. 활성화 중 순간적인 대비 저하를 막기 위해 버튼 색상 전환 애니메이션은 사용하지 않는다. 입력 경계 #78869A와 초점 #2F6FA8은 밝은 표면에서 3:1 이상이다. 성공·주의·오류는 각각 #3F5E31, #76501B, #9A3428과 밝은 전용 배경을 유지한다.

CSS Variables와 Tailwind `@theme inline`을 연결했다. 예: `bg-brand-action text-primary-foreground`, `bg-surface-blue text-ink`. 카드는 12px 모서리와 경계선만 쓴다. Noto Sans KR(빌드 때 자체 호스팅)을 쓰고 본문 15px, 작은 안내는 최소 12px, 모바일 입력은 16px로 표시한다. 교육철학과 수업 안내 문구는 보존했다.

## 이미지

### 공식 앱 아이콘 — 물음표 아이콘 (2026-10-25 교체)

`public/brand/muleum-icon-question.png`(1254×1254, RGB)는 사용자가 제공한 원본이다. 하늘색 둥근 사각형 안에 삼각형 그물(low-poly) 선으로 그린 물음표가 있고, 둥근 모서리·바깥 그림자·흰 여백이 이미지 안에 그려져 있다. 원본은 고치지 않는다.

| 파일 | 크기 | 만든 방법 | 용도 |
| --- | --- | --- | --- |
| `muleum-icon-question.png` | 1254 | 원본 그대로 | 화면 로고: 상단 내비게이션, 로그인·초대·첫 로그인 확인 화면, 설치 안내 페이지 |
| `muleum-icon-question-192.png`, `-512.png` | 192, 512 | 원본을 `sips`로 축소 | PWA manifest `purpose: any`, 알림 아이콘(192) |
| `muleum-icon-question-maskable-512.png` | 512 | 정사각형 버전을 99.0%로 줄이고 바깥을 가장자리 하늘색으로 이어 채움 | PWA manifest `purpose: maskable` |
| `muleum-icon-question-apple-180.png` | 180 | 정사각형 버전을 `sips`로 축소 | `apple-touch-icon` |
| `muleum-icon-question-32.png`, `-16.png` | 32, 16 | 정사각형 버전을 `sips`로 축소 | 파비콘 |

- **정사각형 버전**
  - 원본의 둥근 사각형은 가로 142–1110, 세로 128–1115로, 세로가 조금 길다.
  - 그래서 세로 가운데에서 969px 정사각형(가로 142–1110, 세로 138–1106)을 잘라냈다.
  - 모서리·그림자 영역은 주변 하늘색에서 부드럽게 이어 채웠다.
- **maskable 안전 영역**: 물음표에서 중심까지 가장 먼 점은 아래쪽 점(·)의 끝으로, 정사각형 너비의 39.2%다. 가운데 80% 원(반지름 40%) 안에 3% 여유를 두려고 99%로만 줄였다.
- **작은 크기**: 16·32px 파비콘에서도 물음표 모양이 보인다. 다만 선이 가늘어서 색이 옅게 보인다.
- **어두운 배경**: 화면 로고는 원본의 흰 여백까지 그대로 쓴다. 그래서 다크 모드의 헤더·로그인 띠 위에서는 밝은 타일처럼 보인다.
- **크기별 비교 이미지**: `artifacts/icon-question/comparison.png`.
- **만든 도구**: 이미지 처리에는 macOS `sips`와, 이 컴퓨터에 이미 설치된 Pillow·numpy를 썼다. 프로젝트 의존성은 추가하지 않았다.

## 검증 범위

`tests/design.test.ts`는 정확한 팔레트, Tailwind 연결, 본문 4.5:1 및 초점·입력 경계 3:1 대비를 계산한다. `tests/e2e/community.spec.ts`는 공개·학습 화면 15개 경로, `tests/e2e/auth.spec.ts`는 로그인·다섯 역할 홈·마이페이지의 실제 글자 대비와 가로 넘침을 검사한다. 큰 글자는 3:1 기준이다.

브라우저 검사는 Chrome의 데스크톱 1440×1000, 태블릿 768×1024, 모바일 390×844에서 수행한다. 모바일 왼쪽 메뉴, 큰 화면 상단 메뉴, 키보드 순환·Esc 닫기, 감소된 움직임 설정을 유지한다. 실제 기기의 Safari·Android, 화면낭독기·OS 고대비 모드는 별도 확인이 필요하다. 이 검사는 전체 WCAG 인증을 의미하지 않는다.

졸업생은 계정 상태만 안내하며 내부 라운지·모임·게시판이나 존재하지 않는 외부 링크를 추가하지 않았다. 인증·DB·권한·학습 로직은 디자인 변경 대상이 아니다.
